### Deviations from this plan

- **Style** is a button in the home top bar, not only in Settings and the shop. It is the most-used customisation, and four dock actions were still achieved.
- **Quick actions** (joke, kind word, self-care) became one "Cheer up" sheet instead of three buttons.
- **Tablet** gets the same single column, centred and limited to 560 px, rather than a two-column layout.
- The shop uses one column of cards on every size rather than two on wide screens.
- Some sizes (spacing in a few places, the claw machine's drawing) are still plain numbers.

## 1. Why this plan exists

Plan A-00 moved BaoBao's code and behaviour to Flutter. It deliberately did not redesign anything: screens were laid out quickly to get every feature working, and the visual assets were converted rather than reworked. The result behaves correctly under test but, as reported, still looks broken.

**An honest limit:** nobody has seen this app running on a phone. Everything below comes from the reference screenshots the test suite renders (`test/app/goldens/`, `test/core/widgets/goldens/`, `test/features/claw_machine/goldens/`) and from reading the code. Real devices will show more, which is why the first phase is about seeing the app properly.

## 3. Principles

1. **BaoBao and what BaoBao says come first.** On every screen the character and the current line stay in view and readable at the largest text size. Everything else yields space.
2. **Calm, not busy.** One clear main action per screen. Fewer frames, more air.
3. **Nothing is ever cut off.** Text wraps or scrolls. It never overlaps, clips, or breaks mid-word, at 2× text and on a 360×640 screen.
4. **One visual language.** Colours, type sizes, spacing, corner radii, and icons come from one small set of tokens.
5. **Prove it by looking.** Every change is judged from a rendered image, not from the code.

## 4. Decisions

Taken as decided unless the owner objects.

| # | Question | Decision | Why |
|---|----------|----------|-----|
| 1 | Orientation | Portrait only on phones. Tablets rotate and use a centred, width-limited layout. | The characters and claw machine are portrait art. The prototype did the same. |
| 2 | Dark mode | Add a dark theme that follows the system. Dark palette is a deep bamboo green with the same accents. | People use this app at night. |
| 3 | Design direction | Keep the bamboo look, but flatter: frames only for dialogs, the claw machine, and the main call to action. Cards and lists become plain rounded panels with a soft border. | Fixes V-07 and V-09 without losing identity. |
| 4 | Emoji | Bundle a small emoji font containing only the glyphs the content uses. | Fixes V-18 on every Android version and keeps the dialogue's warmth. Needs a licence check (Noto Emoji is open licence). |
| 5 | New character poses | Not drawn by me. The existing illustrations are better than anything built in code. Use the existing face art as an inset badge for anxious and okay, and list real poses as a request to the artist. | Keeps the character consistent. |
| 6 | Everything else visual | Remake freely: backgrounds, icons, prizes, claw machine, app icon, splash, motion. | The owner granted this. |

## 5. Phases

Estimates are rough working days for one developer. R1 and R2 can overlap.

### R0 — See the app properly (2–3 days)

Without this, later phases fix what the test renderer shows and miss what a phone shows.

1. **Layout matrix test.** One test that renders every screen at a grid of conditions and fails on any overflow, clipped text, or overlap:
   - screen sizes: 360×640, 393×852, 412×892, 600×960 (small tablet);
   - text scales: 1.0, 1.3, 2.0;
   - states: idle home, mid-conversation with the longest line and three replies, shop with every item, settings fully expanded, resources for a known and unknown country, each dialog and sheet.
   This must fail today on V-01 to V-03, which proves it works.
2. **Review sheets.** A tool that renders each screen across the matrix into one image per screen, so a person can look at all of them in a minute. Output goes to a git-ignored folder, not into the repository.
3. **Real device screenshots.** Add an integration test that walks the main journeys and saves screenshots, run on an Android emulator in CI (GitHub Actions). Review these artefacts for every pull request. Until this runs, ask the owner for screenshots from their own phone, and add each reported fault to section 2.
4. **Re-render the three backgrounds** and the app icon and splash at actual device sizes, to confirm V-04, V-12, V-16 and find anything else.

**Exit:** the matrix test exists and fails on the known faults; a person can see every screen in every condition in one place.

### R1 — Design system (3–4 days)

1. **Tokens** in one file: spacing scale (4, 8, 12, 16, 24, 32), corner radii (small, medium, large), a type scale of six sizes with weights, colour roles for light and dark, and elevation or border styles.
2. **Components, redefined:**
   - *Panel*: plain rounded surface with a thin border (replaces the bamboo frame for cards, list items, and status chips).
   - *BambooFrame*: kept for dialogs, the claw machine, and the one primary button per screen, and lightened (thinner rim).
   - *Primary / secondary / quiet buttons*: three clear levels, replacing five colour tones.
   - *List row*, *section header*, *chip*: each with fixed minimum sizes and wrapping rules.
3. **Icon set**: draw about 16 icons in the bamboo style as SVG (back, settings, help, shop, claw, style, music, play, stop, call, text, website, heart, star, lock, delete), delivered as one icon widget. Replaces every Material icon.
4. **Dark theme** from the same tokens.
5. **Contrast tests** for every text and background pair in both themes.

**Exit:** no screen uses a hard-coded size, colour, or icon; contrast tests pass in both themes.

### R2 — Layout repair (4–6 days)

Fixes V-01, V-02, V-03, V-05, V-06, V-09, V-10, V-19.

1. **Home.** Replace the single scrolling page with three fixed zones:
   - *Top bar*: name, mood badge, stars, settings. Always visible.
   - *Stage*: speech bubble over the character. The bubble has a maximum height and scrolls inside itself for long lines (V-19). The character takes whatever space is left and shrinks, never disappears, before anything else gives way.
   - *Dock*: at the bottom, a panel with its own maximum height (about 40% of the screen) that scrolls inside itself.
2. **Idle dock**: one large primary button ("How are you feeling?") and, beneath it, a single row of three round icon buttons with labels (Pick-me-up, Shop, Claw). "Pick-me-up" opens a small menu with joke, kind word, self-care. "Style" moves into Settings and into the shop's top bar. Seven buttons become four.
3. **Conversation dock**: replies as full-width buttons stacked, "End chat for now" as a quiet button, and the feature suggestion as a chip above them.
4. **Get help.** The region selector becomes a full-width row under its label. Helpline cards stack their action buttons vertically when narrow.
5. **Shop and style.** New item card: large preview on top or at the left that scales with width, name and price below it, one full-width action button. Music preview moves to a play button over the thumbnail. Two columns on wide screens, one on narrow.
6. **Settings.** Group into plain panels; sliders get their value shown at the right; switches get full-row hit areas.
7. **Onboarding, tutorial, unlock.** Same zone logic: character and text fixed, actions pinned to the bottom.
8. **Orientation.** Lock to portrait on phones; tablets get a centred column up to 560 px wide.
9. **Default background** raised to a visible but quiet contrast.

**Exit:** the R0 matrix test passes with no overflow or clipping, and each screen's review sheet is approved by the owner.

### R3 — Art and identity (6–9 days)

Fixes V-04, V-08 (with R1), V-12 to V-16.

1. **Backgrounds, redrawn as three complete scenes** (SVG, built in code with a script so they can be tuned):
   - *Bamboo Grove*: soft sky gradient, layered stalks at three depths, drifting leaves.
   - *Bamboo Clouds*: dawn sky gradient, clouds with depth, stalks fading into mist.
   - *Bamboo Plum*: warm dusk, branch silhouettes with proper blossoms, falling petals.
   Each in light and a darker night variant.
2. **App icon**: proper adaptive icon. Cut the panda out of the existing artwork onto a transparent foreground, sized inside Android's safe zone, with a bamboo-green background layer; plus a monochrome layer for Android 13 themed icons. iOS icon from the same cut-out.
3. **Splash**: centred cut-out of the panda on the app background colour, sized for Android 12's round mask; dark variant.
4. **Claw machine, redrawn:**
   - Cabinet with bamboo-green body, rounded glass with reflection, a lit marquee ("BaoBao" wordmark).
   - A proper claw: three jointed fingers, cable with a slight swing, shadow on the prize bed that grows as it descends.
   - **Themed prizes restored and extended**: apple, carrot, grape, strawberry, bamboo shoot, and a golden star for rare ones, each drawn in a consistent flat style with soft shading.
   - Real controls: a stick and a button that animate when pressed, instead of decorations.
5. **Mood poses**: anxious and okay use the existing face art as a badge beside the hello pose (decision 5). Open a request list for new full-body poses.
6. **Emoji font** subset with a licence check, so every emoji in the dialogue renders on Android 7 and up (V-18). Keep a content test that fails if a new emoji is added without being in the font.

**Exit:** each asset reviewed on its own sheet and in context at 1× and 2× text; the icon verified in a launcher mask preview at three mask shapes.

### R4 — Motion and feel (3–4 days)

Fixes V-20 to V-22. All motion respects the reduced-motion setting and the system setting.

1. **Screen transitions**: a gentle fade and slide shared by every route. Sheets and dialogs scale in.
2. **BaoBao reacts**: a small bounce when you pick a mood, a head-tilt on a joke, a sparkle on a win; the pose cross-fades instead of swapping.
3. **Entrance choreography**: on a new screen, the character, bubble, and dock arrive in sequence over about 400 ms.
4. **Claw machine motion**: eased drop and lift, cable swing, a short pause at the bottom as the claw closes, prize bounce on release, and a burst of stars when stars are won.
5. **Buttons**: press, focus, and disabled states for all three button levels.
6. **Empty and loading states** designed, not blank.

**Exit:** a short screen recording of each journey, reviewed by the owner; no animation runs under reduced motion.

### R5 — Platform finish (2–3 days)

Fixes V-11, V-16, V-17 in practice.

1. Edge-to-edge drawing with correct safe-area handling and status and navigation bar icon colours for light and dark.
2. Android back-gesture preview support; correct behaviour on every route.
3. Large-screen layout checked on the 600×960 case.
4. Splash on Android 12+ and below, light and dark, checked on emulators.
5. Dark theme checked on every screen, including images (character cut-outs on dark backgrounds).

**Exit:** emulator screenshots at three API levels (24, 33, 36) reviewed.

### R6 — Verification and handover (2–3 days)

1. Regenerate all goldens, add the matrix to CI, and keep the review sheets as a CI artefact.
2. Screen-reader walkthrough notes (TalkBack, VoiceOver) updated for the new layouts.
3. Update `README.md`, `CODEMAP.md`, `PROJECT-SPECS.md`, and `LOG.md`.
4. Mark this plan's status and any deviations.

## 7. Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| Faults exist that the test renderer cannot show (real fonts, GPU, device quirks). | Fixes miss what the owner sees | R0 adds emulator screenshots in CI; owner screenshots are logged as defects as soon as they exist. |
| Code-drawn art looks worse than hand-drawn art. | Backgrounds and the claw machine feel generic | Each asset gets its own review sheet before it is wired in; the script-based approach makes tuning cheap; fall back to commissioning if it does not reach the character art's level. |
| The cut-out of the panda from the old JPEG is rough. | Icon and splash look amateur | Try background removal on the existing 1024 px art; if edges are poor, ask for a transparent master from the artist. |
| Emoji font adds size or has licence terms. | Larger app, legal risk | Subset to the used glyphs only (small); confirm the licence before committing the font. |
| Redesigning the home screen changes how people have learned the app. | None yet: there are no users | Do it now, before release. |
| Golden images differ across operating systems. | CI noise | Generate and compare goldens on one pinned CI image only; keep local goldens advisory. |
